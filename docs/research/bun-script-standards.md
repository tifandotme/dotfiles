# Bun script standards

Use mise file tasks for user-facing arguments, help, and completion. Keep Bun for implementation and pin external imports to exact versions when a task needs them. The checkout-only tasks live in `mise-tasks/dotfiles/`, which chezmoi ignores. Keep `updater:clean` dependency-free and keep the `gh` wrapper transparent. Use small, executable checks for behavior worth keeping under test.

## What runs today

The tracked inventory has six runtime entrypoints, one standalone TypeScript check, and five imported or host-loaded files. It includes the extensionless `gh` task and the Herdr entrypoint, which has no shebang. No first-party executable in the inventory uses a Node shebang; the `node:` imports are compatibility APIs running under Bun. This standard does not remove Node from mise or change third-party tools.

## Crust rejects bad input before the command runs

I ran both published releases under Bun 1.4.4 on Box using temporary installs and identical flag definitions. Both support named commands and generated help. Neither needs to run under Node.

| Probe or constraint                                | [Crust 0.6.1](https://registry.npmjs.org/@crustjs/core/0.6.1)                                                                   | [Citty 0.2.2](https://registry.npmjs.org/citty/0.2.2)                                                                     |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `--help`                                           | Help extension printed usage, exit 0, no action                                                                                 | Built-in help printed usage, exit 0, no action                                                                            |
| Unknown flag, missing string value, extra argument | Rejected each, exit 1, no action                                                                                                | Ran the action in each case; unknown flag was present in parsed args, bare string flag was empty, extra arg landed in `_` |
| `--name --dry-run`                                 | Rejected the missing value                                                                                                      | Consumed `--dry-run` as the string value                                                                                  |
| `-- --help`                                        | Passed literal `--help` to the action in `rawArgs`; declared positionals can consume tokens first                               | `runMain` showed help before invoking the action                                                                          |
| Dependencies                                       | Core plus help extension and four distinct Crust transitive packages in the probe lockfile. Requires Bun ≥1.4.0 when using Bun. | One package, no dependencies. Uses `node:util.parseArgs` under Bun with `strict: false`.                                  |

For a standalone CLI that needs its own parser, Crust offers stricter defaults. Mise tasks already have a parser, so they do not need either framework. Sources: [Crust Core](https://crustjs.com/docs/modules/core), [Crust Help](https://crustjs.com/docs/modules/extensions/help), [extension package metadata](https://registry.npmjs.org/@crustjs/extensions/0.6.1), and [Citty source and API](https://github.com/unjs/citty).

The `-- --help` row tests what each parser does when it receives both tokens. The Box shebang probe confirmed that [Bun strips a leading `--`](https://github.com/oven-sh/bun/issues/13984) before the parser sees it. Bun kept `--` when it followed another argument. Preserve the current `gh` boundary and check its actual mise invocation rather than imposing a new separator convention.

The original `machine-map` pilot verified [Bun's versioned imports](https://bun.com/docs/runtime/auto-install) for Crust `0.6.1` without a manifest or lockfile. Bun can fetch packages on first run, and transitive versions are not locked. Keep exact pins for external imports that are still needed. `machine-map` no longer needs Crust, and `updater:clean` should still work offline with a missing package cache.

## Prefer Bun wherever it preserves the contract

1. Start first-party TypeScript entrypoints and standalone checks with `#!/usr/bin/env bun` on line one. Set the executable bit where called directly; preserve chezmoi's `executable_` target behavior and explicit interpreter paths where callers need them. Imported files and host config do not get shebangs.
2. Use `Bun.argv`, `Bun.env`, `Bun.file`, `Bun.write`, and `Bun.which` where they fit. Keep `node:path`, `node:os`, and the filesystem or crypto APIs Bun does not replace cleanly. Examples here: `realpath`, `statfs`, executable-access checks, and atomic `rename`. Never replace an atomic write with a plain overwrite for consistency.
3. Use [`$` from `bun`](https://bun.com/docs/runtime/shell) for normal commands. Interpolate arguments as values or arrays, never as raw command strings. Choose output handling explicitly. Let failures throw unless a nonzero exit is expected, then use `.nothrow()` and check the status. Use buffers for binary output and NUL-delimited output; do not trim bytes as a general rule.
4. Use [`Bun.spawn` or `Bun.spawnSync`](https://bun.com/docs/runtime/child-process) where process control matters: inherited TTY, timeout or buffer bounds, PID, signals, or worker detachment. Keep a short explanation for an exception that is not obvious. The Box probe confirmed that `Bun.spawnSync` throws `ENOENT` for a missing executable and returned `success: false` with no numeric exit on timeout or buffer overflow. Preserve fail-closed behavior when replacing Node result objects.
5. For owned CLIs, reject invalid input before side effects, send errors to stderr, and preserve documented status codes. Keep `#USAGE` with mise for its public help and completion. Keep raw argv for transparent wrappers. Do not change command names, flags, or workflow wiring as a side effect of the runtime migration.

## Keep checks that would catch a real break

The repo has nine `scripts/test-*` files: seven Bash, one Lua, and one TypeScript. The TypeScript storage check passed on Box with `bun scripts/test-storage-cleanup.ts`. Its fixture covers distinct deletion guards, including an active checkout, a changed HEAD, an unreadable inventory, and a busy lock. Six of the nine files are not run by `dotfiles:check`; review their usefulness separately instead of porting or deleting them as part of this change.

- **One entrypoint for checks:** Use `mise run dotfiles:check`. Use `scripts/test-<command>.ts` and direct `bun scripts/test-<command>.ts` invocation for retained Bun checks. Use built-in assertions. There is one file today, so adding `bun:test`, Jest, Vitest, snapshots, or a shared fixture framework buys little. `bun test` is a reasonable built-in runner if multiple files later need discovery or named case filtering; its [discovery rules](https://bun.com/docs/test/discovery) do not match the current `test-*.ts` name by default.
- **One reason per retained check:** Name the regression it catches. Assert public output, exit status, or resulting files. Extend the existing file before creating another. Use throwaway probes for formatting, imports, framework behavior, or refactors; remove them afterward. Do not keep tests for private helpers, wiring, or full help-text snapshots.
- **Scope checks to the risk:** For destructive tools, use a fresh temporary home and local fixture. Exercise both a removable control and protected cases. Group repeated inputs only when they prove the same rule. For platform-specific tools, verify in an isolated environment or on the owning platform without touching live user data. Use a fake `gh` for forwarding checks; no real credentials are needed.

## Migrate one workflow at a time

1. **Checkout tasks moved.** `dotfiles:machine-map` is the Bun file task example. `dotfiles:check` and `dotfiles:check:task-refs` stay Bash. Root `AGENTS.md` records the standard.
2. **Migrate theme and Herdr entrypoints next.** Keep theme arguments and completion in the installed mise tasks. Preserve the Mac GUI PATH, picker, undo, and reload order. Give the Herdr entrypoint a Bun shebang and keep its host-owned interface and worker protocol. Verify the worker starts, survives the hook exit, and stops on idle.
3. **Review `gh` and storage cleanup last.** Keep the transparent `gh` pass-through, inherited TTY, and child status. Keep `updater:clean` dependency-free and preserve its standalone recovery interface, locks, timeouts, and exit codes. Verify recovery with the existing isolated check and a cold cache. Do not run live apply or recover to test it.
4. **Verify each batch with `mise run dotfiles:check`.** Check the installed path as well as the source path for managed files. Report Mac-only checks separately from Box checks. Leave Amp and Finicky host modules and non-Bun tests alone unless a specific behavior requires a change.
