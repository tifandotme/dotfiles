# Rift upstream: workspaces, layouts, and motion

Checked 2026-11-18. Rift [`main`](https://github.com/acsandmann/rift/commit/165e29a567f5858aee2ed09fe9e2233b50b55576) was `165e29a567f5858aee2ed09fe9e2233b50b55576`. GitHub's [latest release](https://github.com/acsandmann/rift/releases/tag/v0.8.3) was `v0.8.3`, published 2026-11-16 at 02:48:23 UTC, at commit [`23d52b5a36df2597e2880ca243061445d989f5b4`](https://github.com/acsandmann/rift/commit/23d52b5a36df2597e2880ca243061445d989f5b4). The release contains both universal macOS binary and `.app` archives. [`main` is five commits ahead](https://github.com/acsandmann/rift/compare/23d52b5a36df2597e2880ca243061445d989f5b4...165e29a567f5858aee2ed09fe9e2233b50b55576). The upstream [documentation snapshot](https://github.com/acsandmann/rift-docs/commit/7280b0881f3f1a59a63f9f5ef0bdc3e57a95c17a) is newer than the release. Where the guide, bundled config, and implementation disagree, use the corresponding version's code.

## Performance and animations

The [manifesto](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/manifesto.md#L1-L16) favors performance and accepts private APIs to avoid some blocking Accessibility (AX) work. The [README](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/README.md#L36-L46) advertises performant animations; the demo is not a benchmark. The source shows a split: private SkyLight calls handle tasks such as [window hit testing](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/sys/window_server.rs#L678-L702), while [window geometry setters](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/app.rs#L809-L843) still use AX.

- Rift runs a dedicated [`rift-presenter` thread](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/reactor.rs#L1040-L1057). It uses [per-display display links and coalesced wakes](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/reactor/animation.rs#L761-L812), with [timer fallback](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/reactor/animation.rs#L846-L878) and [frame batches per app handle](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/reactor/animation.rs#L95-L135). The high-frequency AX writer [skips geometry reads](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/app.rs#L1003-L1023); ordinary frame reconciliation [reads geometry back](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/app.rs#L1531-L1565). `v0.8.3` already [defers Enhanced UI suppression until an animation frame needs resizing](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/src/actor/app.rs#L1297-L1343).
- Ordinary transitions ease position and step size at halfway, with a final size write. Scrolling has a separate viewport spring; it reconciles size at the transition boundary and can move at the accepted size on display ticks. See [transition sampling](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/reactor/animation.rs#L1531-L1540) and [viewport state and frame preparation](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/reactor/animation.rs#L185-L280). The virtual-workspace switch path [applies frames immediately](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/reactor/animation.rs#L1142-L1163) and [batches position-only writes if size is unchanged](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/reactor/animation.rs#L1203-L1267). Enabling layout animation does not imply a native-style workspace transition.
- The [bundled config](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/rift.default.toml#L4-L12) sets `animate = false`, `animation_duration = 0.3`, and `animation_fps = 100.0`. The comment about `0.0` is stale: the [validator requires positive FPS](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/src/common/config/types.rs#L1568-L1584). Scrolling's [separate `animate` setting defaults to true](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/common/config/types.rs#L1313-L1320). An explicit layout setting overrides the general switch and Low Power Mode in the [animation decision](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/reactor/animation.rs#L1005-L1028). The configured FPS is a scheduling limit, not a measured delivery rate.

## Virtual workspaces

Rift workspaces group managed windows without creating macOS Spaces. Inactive workspaces [park their windows off-screen](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/layout_engine/engine.rs#L3069-L3109), including floating windows. The [parking algorithm](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/model/hidden_window_placement.rs#L79-L144) scores both bottom corners and side placements for overlap. The [upstream guide](https://github.com/acsandmann/rift-docs/blob/7280b0881f3f1a59a63f9f5ef0bdc3e57a95c17a/src/content/docs/guides/workspaces.md#L73-L97) warns that a parked window can still appear on another display if all candidates overlap. Display arrangement and the window's size matter.

- `per_display` keeps a separate numbered list for each native desktop on each display. `global` gives workspaces one shared catalog with one owner at a time. A workspace on another visible managed display can be selected there; its windows are not mirrored. The [store filters eligible targets](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/model/virtual_workspace.rs#L466-L517) and [uses per-desktop scope on one display](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/model/virtual_workspace.rs#L420-L435) even with `global` configured. In `per_display`, moving a workspace to another display [moves its windows into the destination workspace at the same index](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/layout_engine/engine.rs#L3610-L3654); in `global` the [workspace itself changes owner](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/model/virtual_workspace.rs#L568-L597).
- Set `mode` explicitly if the distinction matters. On both revisions, a missing config file uses the [bundled TOML](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/common/config/parse.rs#L12-L18), which selects [`per_display`](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/rift.default.toml#L291-L314). The [`WorkspaceMode` field default](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/common/config/types.rs#L29-L54) for an existing `[virtual_workspaces]` table with no `mode` is `global`. The bundled count is four; the [limit in code](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/common/config/types.rs#L14) is 128, despite the old `1–32` comment. Workspace indices in bindings are zero-based. The [bundled rules](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/rift.default.toml#L298-L368) document focus memory, wrap/back-and-forth, per-workspace layout and global display preferences, and app rules for assignment, floating, placement, size, focus, and admission.
- `v0.8.3` can [leave a later native desktop empty](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/src/model/virtual_workspace.rs#L877-L942) in global mode; moving away its last workspace [repairs activation without seeding a replacement](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/src/model/virtual_workspace.rs#L553-L580). On `main`, [global seeding](https://github.com/acsandmann/rift/commit/b2f93252e0b07d27bd865c8851ee09b05050e946) gives accepted visible managed desktops a workspace and replaces the last one after an explicit move. Automatic seeds can go beyond the creation limit; an explicit move that needs a replacement is refused at the limit. Reconnecting or reordering displays does not rerun the initial allocation. The [main-branch guide](https://github.com/acsandmann/rift-docs/blob/7280b0881f3f1a59a63f9f5ef0bdc3e57a95c17a/src/content/docs/guides/workspaces.md#L99-L142) describes this newer behavior, including display-rule fallback and restoration after reconnect.

## Layouts and bindings

Rift offers Traditional (tree splits), BSP (binary splits), Master-stack, Stack (accordion), Scrolling (columns), and Floating, with Traditional as the bundled default. Choose a global default, use workspace rules for exceptions, or change a workspace's layout at runtime. [Layout guide](https://github.com/acsandmann/rift-docs/blob/7280b0881f3f1a59a63f9f5ef0bdc3e57a95c17a/src/content/docs/layouts/index.md#L6-L22); [modes and rules](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/rift.default.toml#L316-L331).

The [binding reference in the release config](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/rift.default.toml#L424-L498) covers directional focus and movement, resize, grouping, orientation, floating, layout fullscreen with or without gaps, movement between workspaces and displays, and shell commands. Moves to a workspace can optionally follow the window. `Alt` means Option; `Meta` means Command. TOML supports reusable modifier combinations and ordered command arrays. A custom `[keys]` replaces the bundled keymap; a [binding mode](https://github.com/acsandmann/rift-docs/blob/7280b0881f3f1a59a63f9f5ef0bdc3e57a95c17a/src/content/docs/reference/configuration/binding-modes.md#L15-L39) replaces the active map until switched back, with unbound keys passed through. The [parser rejects conflicting bindings within a mode](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/common/config/parse.rs#L146-L186).

Command names establish functional overlap with other tilers, not behavioral parity. For instance, the [engine delegates grouping to the selected layout](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/layout_engine/engine.rs#L2780-L2810); master ratio/promotion and scrolling strip/column commands are layout-specific. `toggle_fullscreen` [acts on the Rift layout selection](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/layout_engine/engine.rs#L2740-L2769), so it is not the macOS green-button fullscreen action.

Display commands accept direction, index, or UUID. For a workspace move with directional wrapping, [`main` excludes the source display](https://github.com/acsandmann/rift/commit/fbf4bb6bef222db7507431dbb821f747b5bbc683) from the wrapped search. `v0.8.3` can pick the source when displays overlap on that axis.

## Mouse and focus

- The [bundled settings](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/rift.default.toml#L21-L45) enable focus-follows-mouse, mouse-follows-focus, and cursor hiding after warping. Hover [requests both raise and focus](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/reactor/events/window.rs#L444-L476), so it is not a focus-without-raise mode. The [focus path](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/reactor.rs#L5876-L5914) can defer pointer warps until after layout or workspace changes; menus, Mission Control, and certain windows [suppress hover focus](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/reactor.rs#L6174-L6186). `main` excludes [nonactivating attached windows](https://github.com/acsandmann/rift/commit/ecdee64e52855b4fb8d13f4441b108cefd866c88) as hover blockers and honors [`manage = true` for eligible `AXDialog` windows](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/model/reactor.rs#L118-L135), while still vetoing native transients and minimized windows. These fixes are not in `v0.8.3`.
- [Native title-bar dragging and Fn-primary drag](https://github.com/acsandmann/rift-docs/blob/7280b0881f3f1a59a63f9f5ef0bdc3e57a95c17a/src/content/docs/guides/window-management.md#L40-L46) use tiled drop targets. The [default](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/rift.default.toml#L269-L289) swaps on a center drop, optionally stacks instead, and inserts at edges. Modifier buttons can [move or pass through](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/src/common/config/types.rs#L729-L779), not modifier-resize. Native resize is separate and [does not target another tile](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/drag.rs#L425-L461).
- Workspace swipes and Scrolling column gestures are [separate opt-ins](https://github.com/acsandmann/rift-docs/blob/7280b0881f3f1a59a63f9f5ef0bdc3e57a95c17a/src/content/docs/guides/window-management.md#L114-L155). The layout under the pointer determines the handler. Scrolling can hand off to a workspace swipe at the strip edge. Rift can consume handled horizontal swipes to prevent macOS or the foreground app responding too.

## Native Spaces and permissions

Rift [exits with an error](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/src/bin/rift.rs#L156-L179) if macOS **Displays have separate Spaces** is off. This is independent of Rift's workspace mode. [Accessibility access is required](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/src/sys/accessibility.rs#L61-L88) and [management starts disabled by default](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/src/common/config/types.rs#L521-L528); the [bundled activation key](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/rift.default.toml#L500) is Option-Z. The README [says SIP can stay enabled](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/README.md#L36-L46). The manifesto's statement about native Spaces and SIP expresses a project boundary, not a claim that Rift cannot observe or navigate existing Spaces.

Rift [reads native Space state](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/sys/screen.rs#L716-L757) and [reconciles window membership after macOS Mission Control](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/actor/reactor.rs#L6265-L6284). Its [native Space CLI](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/src/bin/rift-cli.rs#L278-L287) exposes management toggle and adjacent switching. Switching [posts synthetic gestures](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/src/sys/space_switch.rs#L170-L223), with separate paths before and from macOS 27; despite CLI help listing up/down, the [implementation only acts on left/right](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/src/sys/space_switch.rs#L448-L463). This surface does not create, reorder, or address native Spaces by index. Rift preserves workspace membership for native fullscreen windows and [excludes them from geometry writes](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/layout_engine/engine.rs#L3105-L3109).

Rift's own [optional Overview](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/rift.default.toml#L202-L211) is distinct from macOS Mission Control. It can [show virtual workspaces and accept window drops between them](https://github.com/acsandmann/rift/blob/23d52b5a36df2597e2880ca243061445d989f5b4/README.md#L34-L37); Screen Recording permission is [for window previews](https://github.com/acsandmann/rift/blob/165e29a567f5858aee2ed09fe9e2233b50b55576/src/ui/settings/interface.rs#L248-L296). `main` also has an [Overview open/close performance change](https://github.com/acsandmann/rift/commit/8d937711a934b963d13505c65813993ade93e9f5) absent from the release.

## Untested on macOS

This is source and release review only. No Mac run, upstream test suite, or benchmark was performed. Actual animation cadence, latency, CPU cost, and private API reliability across macOS versions remain unmeasured. Display parking and reconnection, native Space switching with SIP enabled, fullscreen coexistence, gesture conflicts, and focus behavior with specific apps or dialogs still need runtime verification. The command surface does not establish compatibility with any local keymap or workflow.
