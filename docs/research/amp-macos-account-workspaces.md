# Amp personal and Hadl workspaces on the 8 GB M1

Keep the official Amp app with one window per account. Move Hadl to `4_dev_work` with ⌘⇧4 and leave Personal on `2_dev_personal`. This preserves native sign-in and link handling without adding a second app instance. If browser link routing matters more than having both accounts in the native client, use Amp web in the existing Helium Work profile for Hadl.

## What the installed apps expose

On this Mac, two Amp windows reported the same `com.ampcode.amp.macos` bundle ID. One current title contained `HADL`; the other did not. That snapshot does not establish that the token is an account label or is present when the window first appears. [AeroSpace documents the timing caveat](https://nikitabobko.github.io/AeroSpace/guide#on-window-detected-callback). The installed 0.21.3-Beta also supports [matching bundle path and title](https://nikitabobko.github.io/AeroSpace/commands#test). If a reliable account marker is confirmed across windows and relaunches, put the Hadl title rule before the existing Amp catch-all.

[Amp documents multiple signed-in accounts](https://ampcode.com/docs/apps#sign-in-and-accounts) and [account-aware incoming thread links on macOS](https://ampcode.com/docs/apps/mac#open-threads-from-links). Neither establishes that Finicky receives the originating Amp account for outbound links. The local Finicky config already routes known Hadl domains, Linear paths, and GitHub organization paths to Helium Work; its Claude Hadl catch-all uses a distinct opener bundle ID.

The local `claude:setup` task explicitly selects an Electron user-data directory, sets `CLAUDE_CONFIG_DIR`, changes bundle identity, removes URL registrations, and re-signs the copy. Amp documents no equivalent desktop profile flag. The signed Amp bundle declares app-group and Keychain entitlements, associated domains, push, and custom URL schemes for native auth and handoff. Copying it does not establish separate credentials or app data. Changing the identity and re-signing could affect those capabilities. Test any proposed clone's sign-in, link handling, and update behavior before relying on it.

## RAM on this Mac

With two windows open, `vmmap -summary` measured the single Amp app process at about 85 MiB physical footprint, excluding WebKit helpers. The machine had about 2.7 GiB of swap in use system-wide. Neither number measures the total cost of Amp or the incremental cost of a clone. No cloned instance was launched or benchmarked.

For a fair comparison, run the same two accounts and representative threads in each setup, with the same other apps and executor. Watch Activity Monitor's [Memory Pressure and Swap Used](https://support.apple.com/guide/activity-monitor/view-memory-usage-actmntr1004/mac) over several minutes of normal switching. Compare pressure, growth in swap, and responsiveness rather than a single swap reading. Keep local-runner workloads out of this comparison or hold them constant.
