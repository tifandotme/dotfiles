# Amp artifacts and Box sharing

Checked 2026-11-06. Amp announced artifacts on [2026-11-02](https://ampcode.com/news/artifacts). The current [threads documentation](https://ampcode.com/docs/threads#artifacts) describes editable documents attached to a thread.

## Recommendation

Keep Tailscale Serve and Funnel for existing file and interactive HTML sharing. Use Amp artifacts for collaborative plans, reports, and notes when their thread-linked lifetime and sharing rules are acceptable. Pilot visual artifacts for self-contained wireframes before considering migration. Artifacts have a 2 MB limit, and thread-stored images break for readers who access a document through its workspace or public link. Test representative interactions and access modes before changing the workflow. [Amp threads](https://ampcode.com/docs/threads#share-an-artifact); [Box sharing workflow](../dotfiles-workflows.html).

## What Amp documents

- **Documents and limits.** A document artifact uses Markdown and can contain headings, lists, checklists, tables, code, images, and interactive views. A thread can hold many artifacts in folders. Amp states: "Each artifact holds up to 2 MB." That is an artifact limit, not the attachment upload limit. Document export options are Markdown, HTML, and print to PDF. [Amp threads](https://ampcode.com/docs/threads#artifacts).
- **Editing and revisions.** The agent, thread owner, and eligible workspace participants can edit. Each save makes a revision. An agent's stale update is refused; the agent merges against the newer revision instead of overwriting it. Another thread's agent can edit when its user has permission. A copied artifact is new and does not include the original's comments. The artifact tool says earlier versions are not kept. The docs do not specify comment permissions or notifications. [Amp threads](https://ampcode.com/docs/threads#artifacts); the current thread's artifact tool guidance.
- **Access.** The default is "Same Access as Thread" and follows later thread visibility changes. "Workspace Members" lets workspace members read the artifact even without thread access, but not edit it. "Anyone with the Link" permits access without signing in. People who can open the thread and belong to its workspace, and the owner of a personal thread, can edit; workspace admins accessing through audited access get a read-only view. Workspace admins can disable public artifact links, including existing links. Public URLs should be treated as bearer links and shared only for content safe for anyone holding the URL. [Amp threads](https://ampcode.com/docs/threads#share-an-artifact).
- **Images.** Amp says images added to documents are stored with the thread: "only people who can open the thread see them"; workspace-link and public-link readers see broken images. Deleting an artifact leaves its images until the thread is deleted. The rule concerns thread-stored images; Amp does not say in this section that it applies to self-contained visuals. [Amp threads](https://ampcode.com/docs/threads#share-an-artifact).
- **Lifetime.** Deleting a thread deletes its artifacts. Archiving a thread leaves its URL readable; Amp does not state a separate artifact retention period or public-link expiry in the artifact docs. Amp's security page says thread data is removed within 30 days of explicit thread deletion; it does not separately specify a physical deletion window for artifacts. Export important documents independently. [Amp threads](https://ampcode.com/docs/threads#organize-threads); [Amp security](https://ampcode.com/security#thread-data).
- **Attachments are separate.** Amp accepts screenshots, video, audio, PDFs, logs, spreadsheets, datasets, archives, and other files as thread attachments. The normal limit is 100 MB per file; users with the higher limit can upload up to 512 MB. Attachments are stored copies with thread access checks unless published; temporary attachments expire after a few hours. Publishing generated files exposes them to anyone with the URL. These rules do not establish that arbitrary files become editable artifacts. [Amp files and attachments](https://ampcode.com/docs/orbs/files-and-attachments).
- **Pricing and availability.** Amp says the free Hobby tier includes "All product features" and the artifact tool is available in every user-selectable agent mode and Space. Teams have no extra charge. Agent model and some tool usage can consume credits; Amp-hosted orbs are billed separately. Amp does not publish a separate artifact storage or sharing fee in the cited pricing page. [Amp pricing](https://ampcode.com/docs/pricing); [Amp threads](https://ampcode.com/docs/threads#artifacts).

## Visual artifacts

The official [creating-views skill](https://raw.githubusercontent.com/ampcode/official-plugins/main/skills/creating-views/SKILL.md) describes publishing a complete HTML page as a visual artifact with `kind: "visual"`, embedding it in a reply or document, and opening it for sharing. The artifact tool accepts a local file via `content_path`, including on Box. Each publish replaces the page so embeds show the latest revision. The inline view frame blocks network requests, storage, popups, and form submission; inline CSS, JavaScript, images, and data instead. The skill recommends keeping a page under 100 KB, which is guidance, not the documented 2 MB artifact limit. Clicks and keyboard interaction work within the frame, but individual pages still need testing. Behavior of a visual artifact opened directly, including public access and export, needs verification.

On 2026-11-06, `tailscale funnel status --json` showed two public wireframe mounts. Their source files were 24,217 and 80,304 bytes, both below the 100 KB recommendation. A source scan found no external resource references among script, stylesheet, media and iframe sources, CSS imports, or fetch calls; it found only local SVG fragment references. This does not prove every interaction works or that dynamically constructed requests are absent. The files remain shared through Funnel and were not published to Amp.

Amp stores thread data in a multi-tenant Google Cloud project in the US and states that server data is encrypted at rest and traffic uses TLS. Model providers can receive content used for inference; their retention terms depend on the connection and account. Publishing either an artifact or a Funnel file makes its content available to link holders, and revoking access cannot recall downloaded copies. [Amp security](https://ampcode.com/security#data-security--retention); [sharing skill](../../dot_agents/skills/sharing-public-files/SKILL.md).

## Before migration

Test both wireframes as visual artifacts, including their interactive controls. Test a document with a thread-stored image. Check each as the owner, a workspace member without thread access, and a signed-out public reader; also check export and revocation. Confirm with Amp how direct shared visuals handle dependencies, whether public links expire, how comments and revision recovery work, and whether additional storage or sharing limits apply. This research did not create or publish a test artifact.
