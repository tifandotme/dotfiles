Start & maintain

Update the machine & reclaim space

Cleanup is not required before package updates.

  1. Audit onlymise run updater:clean --auditAdd --check for a cheap free-space check; exit 3 means below target.
  2. Clean eligible itemsmise run updater:clean --applyInactive merged worktrees and unused allowlisted caches only. No further approval needed. Target: 10 GiB free on every machine.
  3. Update packagesmise run updater:start

Safe caches: Bun downloads, npm, uv prune, and Go build cache, only when not in use. --worktree PATH narrows worktrees, not cache cleanup. Agents check before large builds, pulls, or installs and apply on low space or ENOSPC.

Active, dirty, locked, primary, current, and runner-registered worktrees stay. A process or terminal session inside a worktree keeps it. No installed-version or package removal, Go module cache, Docker changes, Trash, Mole, or production changes. If safe cleanup is insufficient, report measured free space without broadening cleanup.

Create cheap worktrees with git-twig

  1. Creategit -C REPO twig new -b BRANCH ../REPO-BRANCH HEADClones committed files copy-on-write. Add TWIG_TRACE=1 to see the backend.
  2. Agent threadsAgent guidance tells agents to use git twig new. create_thread with worktree and the picker's New Worktree button use plain Git.
  3. Removegit twig remove PATHAmp's Archive and Remove Worktree does not clean up Twig worktrees.

On box, ~/projects is a 15 GB sparse XFS image (/var/lib/twig.img) mounted from /etc/fstab. Root free space backs the image, so keep root free space above the image's unused part; run mise run updater:clean --check to see it.

Only git init run from inside ~/projects/work in an interactive shell starts on main. Elsewhere it starts on master. Do not add a conditional includeIf to the Git config: it forces Twig onto stock Git.

Set up a new machine

  1. PrerequisitesInstall chezmoi; on macOS install Homebrew and Xcode tools
  2. Bootstrapchezmoi init --apply git@github.com:tifandotme/dotfiles.git
  3. FinishUnlock age key; on box, approve the sudo prompt if it needs to add Zsh to /etc/shells; open a new SSH session

Applies macOS-only configuration on the main machine and host-specific configuration on the Ubuntu VPS box. SSH access is needed for external repositories.

Work with Git and remotes

  2. Remotegit push and gh pr create run normally, any day

mise run commit:generate generates a message and commits staged changes. Claude uses the personal OAuth token through claude:personal; --agent pi keeps Pi authentication unchanged. On macOS, press C in lazygit's files panel to choose either generator.

Launch coding agents

  1. From project directorypi or claude
  2. AutomaticClaude MCP setup provisions fff and MCPVault on both profiles and prunes other user-scope servers. Remote MCPs (Linear, Context7, Tavily) are claude.ai connectors managed in the UI; the Hadl profile denies unwanted connectors through deniedMcpServers. Amp remote MCPs stay account-managed.
  3. AutostartBox starts box-amp-personal and box-amp-work at boot; macOS starts macbook-amp-personal and macbook-amp-work at login. All sessions run in tmux. Amp runners restart five seconds after exit.Attach with tmux attach -t SESSION. Start manually with mise run agents:start personal|work; stop with mise run agents:stop personal|work. Box runs Amp only; Claude Code is not installed there. Personal runners (box, macbook) serve the chezmoi directory; work runners (box-work, macbook-work) serve ~/projects/work. Each runner starts in its own projects directory.

Claude's statusline starts with blue PERSONAL or orange HADL. Personal OAuth keeps the PERSONAL label even with the Hadl profile. nvimg opens Neovim at the Git root.

Personal accounts are the default. Under ~/projects/work, mise selects the Hadl Amp key, amp-hadl settings, claude-hadl profile, and hadl gcloud configuration at launch. Amp Hadl commits carry no Amp-Thread-ID trailer. Leaving the directory restores personal selection for new processes; running agents keep their account. Shell wrappers and Box launch tasks use mise explicitly. GUI apps do not inherit directory-scoped selection.

Claude profiles share managed settings, coding rules, hooks, keybindings, and RTK, but keep logins, history, trust, agents, and skills separate. Each global CLAUDE.md contains only its own Linear workspace and gcloud account. Hadl production safeguards live in ~/projects/work/AGENTS.md, imported by the adjacent CLAUDE.md. After applying, sign in once with mise exec -C ~/projects/work -- claude auth login --claudeai and confirm with mise exec -C ~/projects/work -- claude auth status. Run mise run claude:extra-usage from the intended project to report only that profile's usage.

Account labels are bold. With personal OAuth in the Hadl profile, the statusline shows orange PERSONAL: the label identifies the account, and the color identifies the profile.

To continue with personal Claude OAuth on macOS, exit Claude and run mise run claude:personal -- --resume SESSION_ID from the same worktree. This keeps the selected profile and saved login. Generate a personal token with claude setup-token, then paste it into mise run claude:personal --store-token. Chezmoi encrypts it separately from ~/.secrets; only this launcher exports it. Check /status and account-provided MCP access before continuing. Setup and verification.

Amp runners allow portals. Ask Amp to start a dev server and open it from the thread’s Portal tab. Portal traffic uses Amp’s tunnel; Tailscale file links remain separate.

On box, ~/projects/ is served directly at https://box.javanese-pound.ts.net:8443/. Agents link to live files without copying them. Connect the viewing device to Tailscale. Links stop working when files or worktrees are deleted.

Ask an agent to share a selected file publicly with sharing-public-files. Funnel uses port 10000, while port 443 serves app domains and port 8443 stays private. Shares can expire or remain public until stopped.

Global workflow tasks

  • mise tasks ls lists tasks from any directory; Tab completes task names and declared choices.
  • mise run agents:status shows the local Amp runner tmux sessions. Start or stop one with agents:start personal|work or agents:stop personal|work.
  • mise run db:list lists connection metadata; mise run db:tunnel core_db_staging opens one tunnel; without an argument it opens every missing one.
  • mise run db:psql core_db_staging -- -Atc 'select 1' uses a fresh IAM token. If the work account needs reauthentication, DB tasks use GCLOUD_PASS from ~/.secrets.
  • On Mac, mise run helium:run starts Helium for Agents. mise run helium:setup work creates the Work instance. mise run claude:setup builds the isolated Claude Hadl desktop app (HADL sign-in, claude-hadl config).
  • On Mac, mise run bird:refresh copies the x.com login cookies from Helium into ~/.secrets (AUTH_TOKEN, CT0), commits and pushes the encrypted secrets, and runs chezmoi update on box, so bird works on both. The bird wrapper in ~/.local/bin does this for you: on an X auth failure it refreshes once and retries. On box it triggers the Mac's com.tifan.bird-refresh LaunchAgent over ssh (a plain ssh session cannot read the Mac keychain), pulls the new secrets, and retries. --no-sync skips the commit and box update.
  • Use mise run TASK --help for task arguments. Project tasks can override global names.
